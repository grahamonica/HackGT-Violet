# Integrating VioletReferent into the app

Checklist for wiring the package into `iOS/Violet`. The package itself needs
no changes; everything below happens in the app and its build scripts.

## 0. Verify the package on a Mac (once)

- [ ] From `iOS/Packages/VioletReferent`, run
      `VIOLET_REFERENCE_DIR=<repo>/ml/facequality/training/exports/FaceQuality_reference swift test`.
      The reference folder is gitignored (it contains CelebA faces); get it from
      whoever ran the export, or run `python -m ml.facequality.training.export`
      yourself (training README).
- [ ] All tests pass. Note the printed numbers:
  - `Core ML vs PyTorch`: max difference should be ~0.01.
  - `Vision vs CelebA landmarks`: mean error in eye distances. If one point
    (likely the nose) is consistently off, adjust `VisionFaceAnalyzer.fivePoints`.
  - `end-to-end vs Python`: the combined effect; mean should be well under 0.15.
- [ ] Optional live AWS check: fill in the package's `.env` (copy `.env.example`)
      and add `VIOLET_REKOGNITION_LIVE=1` to the command above. It enrolls,
      searches and removes a test person in a throwaway `<collection>-livetest`
      collection.

## 1. Add the package to the Xcode project

The project is generated by `iOS/scripts/generate_project.rb`; edit that, not
the `.xcodeproj`.

- [ ] Add `Packages/VioletReferent` as a local package and link the products
      `ReferentCore`, `ReferentApple` and `ReferentRekognition` to the `Violet`
      target (next to the existing Meta wearables package). With the xcodeproj
      gem this is an `XCLocalSwiftPackageReference` (`relative_path =
      "Packages/VioletReferent"`) plus one `XCSwiftPackageProductDependency` per
      product; check the generated project opens and builds.
- [ ] Regenerate the project and build.

## 2. Secrets

The app reads the repo-root `.env` through `iOS/scripts/generate_secrets.rb`,
which only passes keys on its allowlist. (The package's own `.env` is only for
running its tests.)

- [ ] Add to the root `.env`:
      `AWS_REKOGNITION_ACCESS_KEY_ID`, `AWS_REKOGNITION_SECRET_ACCESS_KEY`,
      `AWS_REKOGNITION_REGION` (e.g. `us-east-1`), `AWS_REKOGNITION_COLLECTION_ID`
      (a new name such as `violet-demo`; not `violet-fiqa-wild`, which holds the
      CelebA training people).
- [ ] Add the same four names to `allowed_keys` in `generate_secrets.rb`.
- [ ] Expose them from `AppEnvironment` (or pass its raw values) and build the
      config: `RekognitionConfig(values: values)` returns nil if any is missing.

Demo credentials: one IAM user with full Rekognition access
(`AmazonRekognitionFullAccess`) for both search and enrollment. Anyone with the
app binary can extract it, so delete the key after the event (README,
"Rekognition access").

## 3. Enrollment: keep the collection in sync with the app's people

Rekognition only recognizes people enrolled in the collection. The Rekognition
UserId is the app's person ID (`FamiliarPerson.id`), so a match is the person's
ID directly.

- [ ] On launch (or before the first capture): `try await enroller.ensureCollection()`.
- [ ] When a person is added or their photos change:
      `try await enroller.enroll(personID: person.id, photos: [person.frontPhoto, person.leftPhoto, person.rightPhoto])`.
      Re-enrolling replaces the previous faces. Check `photosWithoutFace` and
      tell the user if a photo had no usable face; `noFaceInPhotos` means none did.
- [ ] People that arrive through Mongo sync also need enrolling. Simplest for
      the demo: remember the `updatedAt` each person was enrolled at
      (e.g. in `UserDefaults`) and enroll anyone new or changed after each sync.
- [ ] When a person is removed: `try await enroller.remove(personID: person.id)`.
- [ ] Build the identifier and the enroller from the **same** `RekognitionConfig`
      so they always use the same collection.

## 4. Capture flow

Today `GlassesManager` feeds frames to a `FrameSelecting` and hands one frame to
`OpenAIRecognitionService` after 5 s. Replace that path with the pipeline:

```swift
let model = try await FaceQualityModel.bundled()
let pipeline = ReferentPipeline(
  analyzer: VisionFaceAnalyzer(model: model),
  identifier: RekognitionIdentifier(config: rekognition))

// On the wake word (beginVioletCapture):
await pipeline.begin()
let result = Task { await pipeline.resolve(earliest: .seconds(2), deadline: .seconds(5)) }

// In videoFramePublisher.listen, for each JPEG:
let frame = ReferentFrame(jpegData: jpeg, timestamp: ProcessInfo.processInfo.systemUptime)
Task { await pipeline.consider(frame) }

// Then:
switch await result.value.outcome {
case .identified(let match):  // match.userID == FamiliarPerson.id
case .ambiguous(let options): // several people equally likely: say nothing or ask
case .notRecognized, .poorQuality, .noFace, .failed: …
}
```

- [ ] Stamp each frame with a monotonic time on arrival (`systemUptime`); the
      frame callback has no timestamp of its own.
- [ ] **Check frame orientation once.** Frames go through `UIImage.jpegData`,
      which may record rotation as metadata instead of rotating pixels; the
      analyzer ignores that metadata. Log `image.imageOrientation` for a frame:
      if it isn't `.up`, redraw the image upright before encoding, or Vision
      will see sideways faces.
- [ ] The answer can arrive before the 5 s stream ends; frames after it are
      ignored, so the stream may keep running or be stopped early.
- [ ] Map `userID` back to the `FamiliarPerson` and keep the existing speech and
      logging. Log `result.diagnostics` (counts, timing, scores; never images)
      to tune thresholds on real footage.

## 5. Smoke test on device

- [ ] Enroll one teammate, look at them, say "Violet": expect `.identified` with
      their ID. Then with nobody in view (`.noFace`), and with a stranger
      (`.notRecognized`).
- [ ] Check `diagnostics.secondsToAnswer` and `identificationCalls` look sane.
